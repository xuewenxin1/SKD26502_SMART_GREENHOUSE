# IOT系统架构

## 1. 整体架构

IOT系统包含三大部分，分别是云端后台、前端和设备端。其中前端可以小程序、APP、Web的形式实现。

### 1.1 云端后台

云端后台是整个IOT系统的中枢，负责消息路由，设备/用户管理，业务逻辑。云端后台采用微服务架构进行实现。后端由MQTT Brober (采用EMQX实现)，用户管理与鉴权服务，业务逻辑服务三部分组成。

#### 1.1.1 MQTT Broker

MQTT Broker负责支持MQTT协议通信，采用发布/订阅模型。该服务主要负责对于MQTT消息的路由。

#### 1.1.2 用户管理与鉴权服务

该服务面向MQTT Broker，通过HTTP端口向MQTT Broker提供用户认证，鉴权的接口。负责管理哪些设备可以接入，接入的设备可以订阅/发布哪些主题。

#### 1.1.3 业务逻辑服务

业务逻辑服务负责订阅相关的消息，如温度等，并自动判断是否需要执行某些自动化操作，如温度过高自动发布打开换气的消息。
   
### 1.2 前端

前端主要负责对设备信息进行展示，提供手动控制的方法，并支持对设备进行配对操作。前端通过HTTP协议接入用户管理与鉴权服务，并通过MQTT协议接入IOT消息路由。

### 1.3 设备端

设备端指IOT设备，通常以传感器、执行器的形式实现。设备端负责对IOT场景进行感知和控制。设备端通过MQTT协议接入IOT消息路由。

## 2. 产品与设备抽象

每一类产品都是一类数据与服务的集合，系统通过类目(product)来区分某一类产品。同类目的产品将使用同样的业务逻辑。产品类目使用类目id(product id,pid)进行唯一标识。
在系统使用时，我们认为每一个设备都只能绑定某一个组(group)，每一个组都通过组id(group id, gid)进行唯一标识，而每一个设备都会在其配网时分配一个虚拟的设备id(virtual id, vid),该id用于在IOT系统中唯一确定一个设备，此外还会在配网时为其分配一个登录凭据(device token)，该token是长效token，用于作为MQTT认证的凭据。每一个设备都具有多个属性和动作，我们将属性和动作统一抽象为数据点(data point, dp)。
每一个设备所使用的主题都遵循如下命名规则。

`{pid}/{vid}/{dir}/{dp}`

其中dir标识数据流向，up代表上行，即设备到服务器，down代表下行，即服务器到设备。

针对每一个类目，都将会在系统中注册dp list。该dp list决定了拥有对应pid的产品以及具有访问权限的用户可以订阅/发布关于该pid的哪些主题。

## 3. 用户管理

每一个用户都具有一个唯一标识(user id, uid), 每一个用户可以加入多个组。每一个用户可以管理其组内的设备。

每一个用户都具有一组(uid, token)作为用户认证凭据。用户登录根据不同的前端实现形式可以采用账密/微信认证接口等不同的方式实现，用户通过对应的方式进行登录后将会拿到token,该token会作为MQTT认证的凭据。

## 4. 其他

如果前端系统以Web形式实现，还需要在后端实现用以支持页面显示的Web服务器。
